# Сервер Anomaly co-op одним файлом

## Сборка

Из корня репозитория:

```
node tools/server/build.mjs
```

Нужен Node 24: сервер собирается под ту же версию Node, которой запущена сборка. При первой сборке нужен интернет: `npx` скачивает `postject`, а с nodejs.org скачивается Node для Linux (один раз, сверяется с `SHASUMS256.txt`).

Что получится в `_build/server/`:

| Файл | Что это |
|---|---|
| `anomaly-server.exe` | сервер для Windows x64, ~90 МБ |
| `anomaly-server` | сервер для Linux x64, ~120 МБ |
| `server.cfg` | пример конфига; если файл уже есть, сборка его не трогает |
| `obj/` | промежуточное: код сервера одним скриптом, blob для SEA |
| `cache/` | скачанный Node для Linux |

Как устроено: код из `coop-server/` собирается в один CommonJS-скрипт, а `admin.html` кладётся внутрь. Всё это встраивается в копию `node` — это Node «single executable application». Node-модули из npm серверу не нужны.

## Запуск

Положите исполняемый файл в отдельную папку. `server.cfg` сервер ищет рядом с собой; если файла нет, он запишет туда пример и запустится с настройками по умолчанию. Мир хранится в `data/` рядом с конфигом.

**Windows:** запустите `anomaly-server.exe`. Брандмауэр спросит про сеть — разрешите. Подпись Node в exe после встраивания недействительна, поэтому файл, скачанный из интернета, SmartScreen может придержать: «Подробнее» → «Выполнить в любом случае».

**Linux:**

```
chmod +x anomaly-server
./anomaly-server
```

Нужна glibc 2.28 или новее: подходит любой современный Debian, Ubuntu или Fedora, а Alpine не подходит. Чтобы сервер работал в фоне, запускайте его через systemd, `tmux` или `screen`.

Конфиг можно указать явно: `anomaly-server путь/к/server.cfg` или `anomaly-server --config путь/к/server.cfg`. Переменные окружения `COOP_PORT`, `COOP_HTTP_PORT` и `COOP_ADMIN_PASSWORD` важнее конфига.

Без сборки: `cd coop-server && node index.js`, тогда конфиг лежит в `coop-server/server.cfg`.

## server.cfg

Строки `ключ = значение` по секциям. После `#` идёт комментарий: в начале строки или после пробела, так что `#` внутри пароля допустим. Пустое значение означает значение по умолчанию. Неизвестный ключ сервер пропустит и напишет об этом в лог.

| Секция | Ключ | По умолчанию | Что это |
|---|---|---|---|
| server | `port` | 7777 | TCP-порт для игр, его открывают для друзей |
| | `admin_port` | 8080 | веб-админка; `0` — выключена |
| | `admin_password` | пусто | пароль админки (имя пользователя любое); пусто — придумается и запишется в `data/admin.json` |
| | `data_dir` | `data` | где хранится мир; путь от папки конфига |
| | `max_players` | 4 | игроков на сервере одновременно |
| | `allow_tests` | 0 | тестовый сервер: во внутриигровой админке тест-режимы и читы для себя (бессмертие, телепорт...); `COOP_ALLOW_TESTS` |
| host | `game_dir` | пусто | папка игры для хоста; пусто — без хоста |
| | `exe` | `bin\AnomalyDX11.exe` | exe игры, путь от `game_dir`. Если на этом же ПК играют из той же игры, хосту нужна своя папка с exe (одна копия игры на папку) |
| | `args` | пусто | ещё параметры игры хоста, например своя appdata: `-fsltx ..sgame_host.ltx` |
| | `autosave_minutes` | 5 | автосохранение мира хостом, минут; `0` — выключено |
| | `pause_when_empty` | 1 | больше не действует: живёт ли мир без игроков, решает правило «Оффлайн-симуляция» (`offline_sim`, по умолчанию да) в админке |
| telegram | `token` | пусто | токен бота; пусто — без бота |
| | `admins` | пусто | id админов в Telegram через запятую |

## Хост

Если в `[host]` указана папка игры, сервер сам запускает её без окна и звука (`-coop_host`): это безголовая игра, она держит мир. Хост всегда сим-мастер: ведёт отряды, респавны, выбросы и время там, где нет игроков, сохраняет мир раз в `autosave_minutes` и, пока в мире никого нет, живёт дальше (правило `offline_sim`: время, A-Life, выбросы; автосохранения пустого мира сервер хранит одно, последнее) или стоит на паузе (`offline_sim` выключено). Сам он ни на одной локации не появляется. Игрок, входящий в мир, получает последнее сохранение и журнал изменений после него, так что ни у кого ничего не замирает.

Хост упал — сервер запускает его снова через 5 секунд. После трёх падений за 5 минут сервер оставляет его лежать до `/restart_host`. Нужны файлы игры (db-архивы и gamedata, как у игроков). На Linux хост пойдёт через Wine — это ещё не проверено.

Настройки мира (сюжет, сложность, фракции, правила) в конфиге не задаются: они хранятся в `data/settings.json` и меняются в админке или через бота.

## Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot` и задайте боту имя. В ответ BotFather пришлёт токен вида `123456789:AA...` — впишите его в `token`.
2. Запустите сервер и напишите боту что угодно. Бот ответит, что вы не админ, и назовёт ваш id; этот же id появится в логе сервера. Впишите id в `admins` (несколько id — через запятую) и перезапустите сервер.
3. Уведомления (игрок вошёл или вышел, хост упал, мир не сохранился) бот шлёт только тем админам, которые хоть раз ему написали.

Бот получает сообщения сам, через `getUpdates`, поэтому открывать для него порт не нужно. Один токен — один сервер: если запустить два сервера с одним токеном, они будут мешать друг другу.

Команды: `/status`, `/settings`, `/set ключ значение`, `/factions` (и `/factions id on|off`), `/save`, `/restart_host`, `/kick имя`, `/rollback ревизия`, `/reset_world`, `/logs` (и `/logs имя`, `/logs имя файл`). `/rollback` и `/reset_world` выполняются только после подтверждения — кнопкой или `/confirm` в течение минуты.
