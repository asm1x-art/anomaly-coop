# Ветка render: заимствования из IX-Ray/OGSR (2026-11-02)

Ветка `render`, сделана от shelter 1ad2d4cc. Незакоммиченная работа shelter (трава, `coop.last_shot`, периметр) сюда не входит, при слиянии учесть.
Подробный разбор с объяснениями — Notion «Движок: DLSS и FSR3 — разбор кода».

## 1. Рендер в пониженном разрешении (этап 1 из DLSS/FSR)
- `r__render_scale 0.5..1` + `vid_restart`. Выключается при MSAA и HDR10.
- `CRender::Render` = `scale_begin` → `Render_scene` → `scale_end` (`r4_R_render.cpp`). На время кадра подменяются `Device.dwWidth/dwHeight/fWidth_2/fHeight_2`, `HW.pBaseRT`, `HW.pBaseZB` (`r4_rendertarget.cpp`). Растяжка на экран: `blender_render_scale.*` + `gamedata/shaders/r3/render_scale.ps`.
- Замер: игра упирается в процессор (Кордон 1080p ~187 fps и при 1.0, и при 0.5; GPU 84%). Поэтому этапы 2–7 (mip bias, jitter, векторы движения, FSR3, DLSS) отложены.

## 2. BC7
Работает без правок: D3DX11 читает DDS с заголовком DX10.

## 3. Загрузка уровней
- Таймеры `LOAD_TIMER` (`xrCore/load_timer.h`) по этапам загрузки, строки `* [load] ...` в логе. Счётчики чтения текстур (`dx10Texture.cpp`) и разбора/выполнения скриптов (`script_storage.cpp`).
- Дерево коллизий строится в фоновом потоке для моделей от 20000 треугольников (`xrCDB.cpp`, `MODEL::build`). `-no_async_cdb` — по-старому. Запрос до готовности ждёт (`syncronize`).
- Кэш дерева на диск: только с `-cdb_cache`. На HDD чтение кэша мешает текстурам.
- Кордон, файлы в памяти: этап коллизий 1.6 с → 0.06 с, переход ~7.3 → ~5.7 с.
- Остаток: первый заход — чтение текстур с HDD (10–17 с). Lua при переходе ~0.95 с: разбор всего 0.12 с, остальное — выполнение кода модулей, так что кэш байткода не нужен.

## 4. Мерцание тени солнца на оружии при сильном зуме
- Причина: каскады подгонялись под суженную зумом пирамиду камеры, оружие оказывалось на задней границе ближнего каскада.
- `r2_R_sun.cpp`, `render_sun_cascade`: проекция для подгонки расширяется минимум до `r2_sun_cascade_min_fov` (по умолчанию 60; 1 — старое поведение). Проверено в игре.

## 5. Процессор: замеры и первые исправления
- `prof_stats <секунды>`: сводка кадра в лог (строки `* [prof]`). По каждой метке — мс за кадр в основном и других потоках, вызовы за кадр, самый долгий вызов, разбивка самого медленного кадра. Метки `PROF_EVENT` / `START_PROFILE` считают сами (`xrCore/prof_stats.*`, `profiler.h`). Разбивка по классам объектов идёт через `PROF_STAT_NAMED`, `level.add_call` подписан по файлу и строке Lua.
- Во время сбора в лог пишутся поздние загрузки: `late texture load`, `late sound load`.
- `g_npc_muzzle_shadows 0` (по умолчанию): вспышка выстрела NPC без тени, у актора тень остаётся. В бою +3–12% fps.
- Прогрев звуковых архивов: при запуске фоновый поток с низшим приоритетом диска читает звуковые `.db` (кроме музыки, 894 МБ за ~7 с), и они попадают в кэш Windows. Первая загрузка звука становится < 0.5 мс вместо 10–25 мс. `-no_warm_sounds` выключает прогрев.
- Замер на Кордоне, 1080p:
  - тишина: ~175 fps;
  - бой 8 на 8: 80–130 fps. Отрисовка в основном потоке 3–4 мс, ИИ сталкеров 2.5, кости 1.0, Lua-обработчики 0.8. Второй поток ~7.5 мс за кадр простаивает.
- Открыто: редкий рывок 0.6–0.8 с в `accum_direct_cascade`; один рывок 0.78 с в очереди таймеров Lua.
