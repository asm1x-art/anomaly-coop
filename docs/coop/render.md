# Ветка render: заимствования из IX-Ray/OGSR (2026-11-02)

Ветка `render`, сделана от shelter 1ad2d4cc. Незакоммиченная работа shelter (трава, `coop.last_shot`, периметр) сюда не входит, при слиянии учесть.
Подробный разбор с объяснениями — Notion «Движок: DLSS и FSR3 — разбор кода».

## 1. Рендер в пониженном разрешении (этап 1 из DLSS/FSR)
- `r__render_scale 0.5..1` + `vid_restart`. Выключается при MSAA и HDR10.
- `CRender::Render` = `scale_begin` → `Render_scene` → `scale_end` (`r4_R_render.cpp`). На время кадра подменяются `Device.dwWidth/dwHeight/fWidth_2/fHeight_2`, `HW.pBaseRT`, `HW.pBaseZB` (`r4_rendertarget.cpp`). Растяжка на экран: `blender_render_scale.*` + `gamedata/shaders/r3/render_scale.ps`.
- Замер: игра упирается в процессор (Кордон 1080p ~187 fps и при 1.0, и при 0.5; GPU 84%). Поэтому этапы 2–7 (mip bias, jitter, векторы движения, FSR3, DLSS) отложены.

## 2. BC7
Работает без правок: D3DX11 читает DDS с заголовком DX10.

## 3. Загрузка уровней
- Таймеры `LOAD_TIMER` (`xrCore/load_timer.h`) по этапам загрузки, строки `* [load] ...` в логе. Счётчики чтения текстур (`dx10Texture.cpp`) и разбора/выполнения скриптов (`script_storage.cpp`).
- Дерево коллизий строится в фоновом потоке для моделей от 20000 треугольников (`xrCDB.cpp`, `MODEL::build`). `-no_async_cdb` — по-старому. Запрос до готовности ждёт (`syncronize`).
- Кэш дерева на диск: только с `-cdb_cache`. На HDD чтение кэша мешает текстурам.
- Кордон, файлы в памяти: этап коллизий 1.6 с → 0.06 с, переход ~7.3 → ~5.7 с.
- Остаток: первый заход — чтение текстур с HDD (10–17 с). Lua при переходе ~0.95 с: разбор всего 0.12 с, остальное — выполнение кода модулей, так что кэш байткода не нужен.

## 4. Мерцание тени солнца на оружии при сильном зуме
- Причина: каскады подгонялись под суженную зумом пирамиду камеры, оружие оказывалось на задней границе ближнего каскада.
- `r2_R_sun.cpp`, `render_sun_cascade`: проекция для подгонки расширяется минимум до `r2_sun_cascade_min_fov` (по умолчанию 60; 1 — старое поведение). Проверено в игре.

## 5. Процессор: замеры и первые исправления
- `prof_stats <секунды>`: сводка кадра в лог (строки `* [prof]`). По каждой метке — мс за кадр в основном и других потоках, вызовы за кадр, самый долгий вызов, разбивка самого медленного кадра. Метки `PROF_EVENT` / `START_PROFILE` считают сами (`xrCore/prof_stats.*`, `profiler.h`). Разбивка по классам объектов идёт через `PROF_STAT_NAMED`, `level.add_call` подписан по файлу и строке Lua.
- Во время сбора в лог пишутся поздние загрузки: `late texture load`, `late sound load`.
- `g_npc_muzzle_shadows 0` (по умолчанию): вспышка выстрела NPC без тени, у актора тень остаётся. В бою +3–12% fps.
- Прогрев звуковых архивов: при запуске фоновый поток с низшим приоритетом диска читает звуковые `.db` (кроме музыки, 894 МБ за ~7 с), и они попадают в кэш Windows. Первая загрузка звука становится < 0.5 мс вместо 10–25 мс. `-no_warm_sounds` выключает прогрев.
- Замер на Кордоне, 1080p:
  - тишина: ~175 fps;
  - бой 8 на 8: 80–130 fps. Отрисовка в основном потоке 3–4 мс, ИИ сталкеров 2.5, кости 1.0, Lua-обработчики 0.8. Второй поток ~7.5 мс за кадр простаивает.
- Открыто: редкий рывок 0.6–0.8 с в `accum_direct_cascade`; один рывок 0.78 с в очереди таймеров Lua.

## 6. NVIDIA DLSS (ветка dlss, 2026-11-06)

Этапы (каждый — свой коммит): mip bias → дрожание камеры → векторы движения → NGX DLSS → меню → доводка. Разбор с объяснениями — Notion «Движок: DLSS и FSR3 — разбор кода».

- **Консоль.** `r__dlss_mode off|dlaa|quality|balanced|performance|ultra_performance` (+ `vid_restart`, по умолчанию off, сохраняется в user.ltx). `r__dlss_status` — только чтение: `ok` или причина (`not_nvidia`, `unsupported`, `old_driver`, `no_dll`, `msaa`, `hdr10`, `init_failed`, `no_sdk`, `headless`). Отладка: `r__taa_jitter 1` (дрожание без апскейлера), `r__dlss_mv_debug 1` (векторы движения на экране; шейдеры для них — с запуска игры), `r__upscale_mipbias 0/1`, `r__dlss_reset_distance` (м за кадр: дальше — сброс истории DLSS, телепорт).
- **Меню.** Видео → Дополнительно, после SMAA (`ui_options_modded_exes.script`, тексты `configs/text/*/ui_mm_dlss.xml`). Если DLSS не может работать, вместо пункта — строка с причиной (`r__dlss_status` читается при показе страницы). Выбор режима DLSS сразу ставит MSAA «выкл»; пока режим DLSS выбран, строки MSAA и SMAA заменены пояснением (SMAA движок при DLSS пропускает сам, настройка игрока сохраняется). MSAA вшит в шейдеры при запуске: его смена и включение DLSS в игре, запущенной с MSAA, — с перезапуском игры (меню просит), остальное — `vid_restart`.
- **DLSS и MSAA при запуске.** Если в user.ltx режим DLSS не off и MSAA включён (старый лаунчер, консоль), `CRender::create` выключает MSAA (`r3_msaa`), когда DLSS может работать: в логе «DLSS: r__dlss_mode is on, MSAA (r3_msaa) turned off». До создания рендера `r__dlss_status` = `not_started`.
- **SDK.** В репозитории его нет (лицензия NVIDIA). `tools/dlss/get_dlss_sdk.ps1` кладёт SDK 310.9.16 в `src/3rd party/nvngx_dlss` (gitignore). Без него движок собирается с DLSS off (`no_sdk`). В игру: `nvngx_dlss.dll` и `LICENSE.txt` (как `DLSS-LICENSE.txt`) рядом с exe.
- **Кадр.** `CRender::Render`: `scale_begin` → `r_taa_frame_begin` (дрожание Halton 2,3 в `Device.mProject`/`mProjectHud`, матрицы прошлого кадра) → `Render_scene` → `r_taa_jitter_end` → `phase_dlss_mv` (векторы + глубина из G-буфера) → `scale_end` (DLSS → `rt_dlss_out` → на экран) → `r_taa_frame_end`. UI — после, в полном разрешении.
- **Векторы движения.** Модели (`deffer_model_*.vs`, кости прошлого кадра `sbones_array_prev`, `m_wvp_prev`) пишут свои в 4-ю цель G-буфера (`rt_ssfx_motion_vectors`, формат SSS). Остальное — по глубине и прошлой камере (`dlss_mv.ps`). Шейдеры G-буфера — копии ванильных Anomaly 1.5.3 с правками под `#ifdef DLSS_MV` (движок задаёт его, когда DLSS может работать).
- **Вход DLSS** — готовая картинка после тонмапинга и пост-эффектов (режим LDR, без экспозиции). SMAA, TAA SSS и AA комбайна при DLSS выключены. MSAA и HDR10 с DLSS не работают.
- **3D-прицелы и MSAA** (не DLSS, но найдено при разборе 2026-11-07): с MSAA линза 3D-прицела была пустой — `phase_3DSSReticle` копировал односэмпловый `rt_Generic_0` в MSAA `rt_Generic_temp` и рисовал в `rt_Generic_0` вместе с MSAA `rt_Position`; D3D отвергал и копию, и цели. Теперь `rt_Generic_temp` всегда в один сэмпл (с MSAA в него resolve), сетка рисуется только в `rt_Generic_0`, маска прицела для SMAA при MSAA не пишется.
- **Пустые руки и паркур** (2026-11-07): с DLSS (и с `r__render_scale` < 1) без оружия в руках картинка увеличивалась и двоилась («ломается FOV»; паркур убирает оружие на время подъёма). Кадр начинался с вьюпортом размера экрана (последняя цель — экран в `scale_end`), уровень при split scene рисовался в G-буфер до HUD с этим вьюпортом. Теперь `scale_begin` сразу ставит размер рендера и вьюпорт.
- **Модели, которых не было в прошлом кадре** (руки после паркура, ноги, модели после отсечения): их «прошлые» матрицы и кости были из давнего кадра — DLSS тянул старые пиксели через экран. Теперь такая модель в первом кадре без своего движения: мировая — с камерой, HUD — на месте на экране (`CSkeletonX::_Render`, `g_taa.hud`). `CKinematics::CurrentFrame` был не инициализирован.
