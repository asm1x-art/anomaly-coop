# Мультиплеер: мир на сервере

Начато 2026-10-30, ветка `multiplayer`. Там, где расходится с [host.md](host.md), верен этот документ. Статусы — как в [plan.md](plan.md).

## Цель

Мир живёт на сервере постоянно, и никто из игроков его не держит. Игроки приходят и уходят, но мир не замирает и не откатывается.

Что получится в итоге: упакованный сервер — один исполняемый файл для Windows и для Linux. Рядом с ним лежит конфиг: порт, пароль, путь к игре, токен Telegram-бота и список админов. Миром и настройками управляют через бота или веб-страницу. Сервер можно запустить и у себя на ПК, и на VPS.

Безголовый хост — это движок Anomaly, а ему нужны файлы игры (db-архивы, gamedata). Поэтому в один файл с сервером он не упаковывается: в конфиге указывается папка игры. На Linux Node-часть работает нативно, а хост — через Wine.

## Решения пользователя (2026-10-30)

- Хозяином локации остаётся тот игрок, кто пришёл на неё первым. Он — источник истины для её объектов. Всё, что меняется, в реальном времени уходит на сервер, а с сервера — остальным игрокам.
- Основной сервер работает постоянно. Это Node (хранит состояние, раздаёт его) и безголовая игра — хост. Хост всегда работает сим-мастером: ведёт офлайн-мир (отряды, смарты, респавны, выбросы, время). Сам он ни на одной локации не появляется.
- Полная онлайн-симуляция мира не нужна. Для ивента на локации без игроков отдельно запускается копия игры на этой локации.
- Сохранения свои у каждого игрока. Одиночка сохраняет и загружает только своего персонажа: позицию, инвентарь, деньги, задания, ранг. В группе лидер сохраняет и загружает всех участников разом. Мир не откатывается никогда.
- Предметы при загрузке сохранения не задваиваются: сервер проверяет, что они всё ещё твои.

## Части

### Сервер (Node, упакован в один файл)
- Пересылка сообщений и хранилище — то, что есть сейчас: персонажи, факты, группы, id-блоки, ревизии мира, логи.
- Назначает хозяев локаций (см. ниже).
- Запускает хост дочерним процессом и перезапускает, если тот упал. После 3 падений за 5 минут останавливается и сообщает админам.
- Telegram-бот и веб-админка.
- Конфиг `server.cfg` рядом с исполняемым файлом. Формат — `ключ = значение` по секциям, комментарии через `#`. Каждая настройка подписана в примере.

```
[server]
port = 7777            # порт для игр
admin_port = 8080      # веб-админка; 0 — выключена
admin_password =       # пусто — придумается и запишется в data/admin.json
data_dir = data
max_players = 4

[host]
game_dir =             # папка игры для хоста; пусто — без хоста (мир держит игрок, как раньше)
exe = bin\AnomalyDX11.exe
autosave_minutes = 5
pause_when_empty = 1   # мир стоит, пока в нём нет игроков

[telegram]
token =                # токен бота от @BotFather; пусто — без бота
admins =               # id пользователей Telegram через запятую
```

Настройки мира — сюжет, сложность, фракции, правила — хранятся, как и раньше, в `data/settings.json`. Меняются они через бота или админку.

### Хост (движок с флагом `-coop_host`)
Устройство — как в [host.md](host.md) «Режим `-coop_host`»:
- окно скрыто, кадры не рисуются, фиксированный тик, звук выключен;
- «призрак» стоит на `fake_start`: невидимый, неуязвимый, без потребностей.

Роль хоста:
- сим-мастер всегда;
- хозяином локации не бывает никогда;
- игроком не считается: у него нет тени, марионетки, метки в КПК и новостей «вошёл/вышел»;
- сохраняет мир.

Сервер узнаёт хост по секрету: его выдаёт сервер, а не игрок.

### Игрок
- При входе получает мир, каким его только что сохранил хост, и встаёт в него своим персонажем. Подмена персонажа при загрузке уже есть.
- На локации либо хозяин (пришёл первым), либо видит марионеток хозяина. Всё это уже есть.
- Сохраняет и загружает только себя (в группе — лидер всех).

## Хозяин локации
- Для каждой локации сервер ведёт очередь игроков в порядке прихода. Первый в очереди — хозяин. Сообщение `M_LEVELS` (новое) рассылается всем при каждом изменении: на каждой локации с игроками её хозяин.
- `is_authority(level)` теперь берёт ответ из `M_LEVELS`. Для локации без игроков ответ даёт сим-мастер (хост).
- Хозяин ушёл — роль получает следующий в очереди. Передача марионеток и своего ИИ при смене хозяина уже работает: сейчас хозяин так же меняется, когда уходит младший id.

## Сохранения

### Мир
Мир сохраняет только хост:
- автосохранением (`autosave_minutes`);
- когда входит игрок (он скачивает свежий мир);
- по команде админа;
- при остановке сервера.

Сервер хранит последние ревизии, сколько — задаёт конфиг. Откат мира на одну из них — только аварийный, командой админа.

### Персонаж
- **Личное сохранение** — снимок персонажа: запись (уровень, позиция, деньги, здоровье), личный прогресс (`coop_progress`) и всё, что он несёт, — пакеты предметов с их id. Хранится на сервере: `data/characters/<имя>/saves/`.
- **Групповое** — лидер сохраняет. Снимки всех участников идут под одним именем, загружаются вместе.
- **Загрузка**: игра уходит в меню и загружает мир заново, свежий от хоста, а персонажем ставит снимок. Это тот же путь, что и при входе.
- **Предметы из снимка:**
  - предмет сейчас в другом месте мира (у игрока, на земле, в ящике, у торговца) — не возвращается;
  - предмета в мире больше нет (съеден, израсходован) — возвращается, как при обычной загрузке в одиночной игре.
- Предметы, взятые после сохранения, — вопрос 1 ниже.

## Ивенты на локации без игроков (позже)
- Сервер запускает ещё одну безголовую копию с флагами `-coop_host -coop_level <локация>`. Она загружает мир и встаёт призраком на эту локацию: локация онлайн, копия — её хозяин.
- Пришёл игрок — хозяином становится он, а копия заканчивает работу.
- Порядок «кто пришёл первым» для копии не действует: она уступает любому игроку.

## Протокол (что меняется)
- `M_HELLO`: роль (игрок / хост) и секрет хоста.
- `M_LEVELS` (новое): на каждой локации с игроками — имя и id хозяина.
- `M_ROLES`: сим-мастер — хост, если он есть.
- Хоста нет в `M_PEER_STATE` и в списках игроков.
- Личные сохранения: запрос снимка у игр участников, снимок частями, список сохранений игрока, загрузка. Откаты мира и паузы голосованием уходят.

## Telegram-бот
- Получает обновления длинным опросом (`getUpdates`), поэтому входящий порт не нужен. Внешних библиотек нет, только `fetch`.
- Отвечает только админам из конфига.
- Команды:
  - `/status` — кто онлайн, где, хозяева локаций, хост (работает ли, память, время работы), ревизия и последнее сохранение мира;
  - `/settings`, `/set <ключ> <значение>`, `/factions` — настройки мира;
  - `/save` — хост сохраняет мир;
  - `/restart_host`;
  - `/kick <имя>`;
  - `/rollback <ревизия>` и `/reset_world` — с подтверждением;
  - `/logs <имя>`.
- Сам сообщает админам: игрок вошёл или вышел, хост упал или перезапущен, мир сохранён с ошибкой.

## Упаковка
- Node «single executable application»: код сервера собирается в один скрипт, `admin.html` — внутрь. Скрипт встраивается в `node.exe` (Windows) и в `node` для linux-x64 — его бинарник скачивается при сборке.
- Сборка: `tools/server/build.mjs`. Результат: `anomaly-server.exe`, `anomaly-server` и пример `server.cfg`. Папка `data/` создаётся при первом запуске.

## Открытые вопросы
1. Что при загрузке сохранения с предметами, которые персонаж взял после него? Варианты: вернуть туда, откуда взяты (игра сообщит место, когда предмет берут); оставить у игрока; пропадают. Предлагаю вернуть на место.
2. Смерть, когда помочь некому: откат позиции к последнему личному сохранению (сейчас — к сохранению мира)? Предлагаю так.
3. Пауза мира без игроков по умолчанию включена: в Anomaly время идёт в 6–10 раз быстрее реального.
